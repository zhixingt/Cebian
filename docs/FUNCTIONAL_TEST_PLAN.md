# CebianX 功能测试方案（会话返回 / 文件上传 / 自动滚动）

## 一、测试执行说明

**测试方式**：本方案提供完整的自动化测试用例（Playwright E2E）+ 手动验证步骤。自动化测试可通过 `pnpm test:e2e` 执行，手动测试需在重新加载扩展后按步骤操作。

**前置条件**：
1. 执行 `pnpm build` 生成最新构建产物
2. 在 Chrome 扩展管理页面重新加载 CebianX
3. 确保已配置有效的大模型 API Key（或 Web Provider 已登录）
4. 准备测试文件（见各用例）

---

## 二、会话返回功能测试

### 2.1 测试目标
验证 `lastSessionId` 的保存、读取和恢复机制，确保用户离开会话（如进入设置）后返回时能正确恢复到之前的会话。

### 2.2 自动化测试用例

| 用例ID | 场景 | 前置条件 | 操作步骤 | 预期结果 | 优先级 |
|--------|------|---------|---------|---------|--------|
| **SR-01** | 设置页面返回恢复已有会话 | 已在 `/chat/abc123` 会话中发送过消息 | 1. 在聊天页面发送消息<br>2. 点击 Header 设置按钮进入 `/settings`<br>3. 点击返回按钮 | 返回到 `/chat/abc123`，消息列表完整显示 | P0 |
| **SR-02** | 设置页面返回无会话时回到新聊天 | 未发送过任何消息（`lastSessionId` 为 null） | 1. 打开 sidepanel（默认 `/chat/new`）<br>2. 不发送消息直接点击设置<br>3. 点击返回 | 返回到 `/chat/new`，无错误 | P0 |
| **SR-03** | Sidepanel 关闭后重新打开恢复会话 | 已在会话 `abc123` 中 | 1. 关闭 sidepanel<br>2. 重新打开 sidepanel | 自动导航到 `/chat/abc123`（通过 `pageshow` + `lastSessionId` 恢复） | P0 |
| **SR-04** | 切换会话后返回设置再返回 | 从会话 A 切换到会话 B | 1. 在会话 B 中发送消息<br>2. 进入设置<br>3. 点击返回 | 返回到会话 B，而非会话 A | P1 |
| **SR-05** | 新聊天后返回设置再返回 | 点击"新聊天"按钮进入 `/chat/new` | 1. 点击"新聊天"<br>2. 进入设置<br>3. 点击返回 | 返回到 `/chat/new`（`lastSessionId` 未被新聊天清空） | P1 |

### 2.3 手动验证步骤

```
步骤1：打开 Chrome sidepanel，确保 CebianX 已加载
步骤2：发送一条测试消息（如"你好"），等待 AI 回复
步骤3：记录当前会话 ID（从 URL 或 UI 中可见）
步骤4：点击顶部设置按钮（齿轮图标）
步骤5：在设置页面点击返回按钮（左上角箭头）
步骤6：验证：
  ✓ URL 应回到之前的会话路径（如 /chat/xxx）
  ✓ 消息列表应完整显示之前的对话
  ✓ 不应出现 /chat/new（新会话空白页）
步骤7：关闭 sidepanel（点击浏览器外部或按 Esc）
步骤8：重新打开 sidepanel
步骤9：验证：
  ✓ 应自动恢复到之前的会话
  ✓ 不应显示空白新会话
```

### 2.4 已知问题与验证要点

| 检查项 | 通过标准 | 失败表现 |
|--------|---------|---------|
| `lastSessionId` 存储 | `chrome.storage.local` 中存在 `local:lastSessionId` 键 | 返回时总是回到 `/chat/new` |
| `pageshow` 事件触发 | 从 bfcache 恢复时触发会话恢复逻辑 | 关闭再打开后显示空白新会话 |
| SettingsLayout handleBack | 代码中包含 `await lastSessionId.getValue()` 逻辑 | 返回按钮硬编码为 `/chat/new` |

```

  ✓ 显示加载/解析状态（短暂）
  ✓ 解析后显示为文本附件（而非图片）

步骤4：打开 DevTools Console，检查是否有 pdf.worker 相关报错

  ✓ 单元格数据以 CSV 格式呈现
```

### 3.4 已知问题与验证要点

| 检查项 | 通过标准 | 失败表现 |
|--------|---------|---------|
| `TEXT_EXTENSIONS` 包含 docx/xls/xlsx/pdf | 代码中包含这些扩展名 | 上传 docx 时报"不支持的文件类型" |
| `extractTextFromFile` 被调用 | ChatInput.tsx 中 `.docx/.pdf/.xlsx` 走提取分支 | 这些文件被当作纯文本 readAsText 读取（产生乱码） |
| `mammoth` 动态导入 | DevTools Network 中可见 mammoth chunk 加载 | 上传 docx 后控制台报错 `Cannot find module 'mammoth'` |
| `xlsx` 动态导入 | 同上，xlsx chunk 加载 | 上传 xlsx 后报错 |
| `pdfjs-dist` worker 配置 | `loadPdfJs()` 被调用，workerSrc 指向扩展内资源 | 上传 PDF 后报错 `Setting up fake worker` 或 worker 404 |

## 四、自动滚动功能测试

### 4.1 测试目标
验证新会话中消息发送后自动滚动到底部的行为，以及消息折叠阈值（30行）是否正确生效。

### 4.2 自动化测试用例

| 用例ID | 场景 | 前置条件 | 操作步骤 | 预期结果 | 优先级 |
|--------|------|---------|---------|---------|--------|
| **AS-01** | 新会话第一条消息自动滚动 | 在 `/chat/new` 中 | 1. 发送消息"请写一段长文本"<br>2. 观察消息区域 | 消息发送后自动滚动到底部，显示最新内容 | P0 |
| **AS-02** | AI 长回复自动滚动 | 消息已发送 | 1. 等待 AI 返回长回复（>1000字）<br>2. 观察滚动行为 | 回复生成过程中/完成后自动滚动到底部 | P0 |
| **AS-03** | 从设置返回后滚动 | 已有长对话历史 | 1. 进入设置<br>2. 返回聊天 | 返回到聊天页面后自动滚动到底部 | P0 |
| **AS-04** | 消息折叠 30 行阈值 | AI 返回 >30 行的消息 | 1. 请求"请列出 50 个要点"<br>2. 观察消息显示 | 消息显示前 30 行，底部有"展开"按钮 | P0 |
| **AS-05** | 点击展开后显示完整内容 | 消息已折叠 | 1. 点击"展开"按钮 | 显示完整消息内容，无截断 | P0 |
| **AS-06** | 短消息不折叠 | AI 返回 <30 行的消息 | 1. 请求"你好" | 消息完整显示，无折叠按钮 | P1 |
| **AS-07** | 用户手动滚动后不强制拉回 | 用户向上滚动查看历史 | 1. 发送消息<br>2. 手动向上滚动<br>3. AI 继续回复 | 用户手动滚动后，AI 新回复不强制拉回底部（stickRef = false） | P1 |
| **AS-08** | 多轮对话持续滚动 | 已有多轮对话 | 1. 连续发送 5 条消息 | 每条消息后都自动滚动到底部 | P1 |
| **AS-09** | 消息折叠阈值准确 | 消息恰好 30 行 | 1. 请求生成恰好 30 行的文本 | 不折叠（阈值应为超过 30 行才折叠） | P2 |
| **AS-10** | 展开后再次折叠 | 消息已展开 | 1. 点击"收起"按钮（如果有） | 消息恢复折叠状态 | P2 |

### 4.3 手动验证步骤

```
--- 自动滚动测试 ---
步骤1：打开 sidepanel，确保在新会话（/chat/new）
步骤2：发送消息"请详细解释什么是人工智能，至少 500 字"
步骤3：观察行为：
  ✓ 用户消息发送后，消息列表应立即滚动到底部
  ✓ AI 回复开始生成后，应持续滚动（跟随生成）
  ✓ AI 回复完成后，应停留在底部
步骤4：如果滚动未发生，打开 DevTools Console，检查是否有报错

--- 从设置返回滚动测试 ---
步骤1：与 AI 进行多轮对话，确保消息列表足够长（需要滚动）
步骤2：点击设置按钮进入设置页面
步骤3：点击返回按钮
步骤4：验证：
  ✓ 返回到聊天页面后，消息列表应自动滚动到最底部
  ✓ 不应停留在消息列表顶部或中间

--- 消息折叠测试 ---
步骤1：发送"请列出 40 条生活小贴士，每条一行"
步骤2：等待 AI 回复
步骤3：验证：
  ✓ 消息应显示约 30 行（或根据屏幕高度的等效行数）
  ✓ 第 30 行后应有"展开"或"查看更多"按钮
  ✓ 点击"展开"后应显示完整 40 条
步骤4：发送"你好"
步骤5：验证短消息无折叠按钮

--- 手动滚动保护测试 ---
步骤1：与 AI 进行长对话
步骤2：手动向上滚动查看历史消息
步骤3：发送新消息
步骤4：验证：
  ✓ 新消息发送后不应强制拉回底部（尊重用户手动滚动位置）
  ✓ 但新消息到来时应有轻微提示（如滚动条高亮或新消息标记）
```

### 4.4 已知问题与验证要点

| 检查项 | 通过标准 | 失败表现 |
|--------|---------|---------|
| `messageCount` effect 存在 | chat/index.tsx 中有 `useEffect(() => { requestAnimationFrame(() => scrollToBottom({ force: true })) }, [messageCount])` | 无此 effect，或缺少 `requestAnimationFrame` |
| `maxLines = 30` | Message.tsx 中 `CollapsibleContainer maxLines={30}` | `maxLines={15}`（旧值） |
| `useStickToBottom` 行为 | 用户手动滚动后 `stickRef` 变为 false | 用户手动滚动后仍被强制拉回 |
| `requestAnimationFrame` 延迟 | `scrollToBottom` 在 DOM 更新后执行 | 在 DOM 更新前执行，导致滚动位置不正确 |

## 五、测试执行命令

### 5.1 运行自动化测试

```bash
# 运行所有相关 E2E 测试
pnpm test:e2e e2e/specs/10-auto-core-chat.spec.ts e2e/specs/11-auto-quick-actions.spec.ts

# 运行单个测试文件
pnpm test:e2e e2e/specs/10-auto-core-chat.spec.ts --grep "auto scroll"

# 断点续跑
pnpm test:auto:resume
```

### 5.2 调试检查清单

如果测试失败，按以下顺序排查：

1. **扩展是否已重新加载？** `chrome://extensions/` → CebianX → 点击"重新加载"
2. **构建产物是否最新？** `pnpm build` 后检查 `.output/chrome-mv3/` 修改时间
3. **DevTools Console 是否有报错？** 打开 sidepanel 的 DevTools 检查红色报错
4. **代码修改是否在产物中？** 搜索 `.output/chrome-mv3/chunks/*.js` 确认关键字存在
5. **Storage 中是否有 `lastSessionId`？** Console 中执行 `chrome.storage.local.get('local:lastSessionId', console.log)`
