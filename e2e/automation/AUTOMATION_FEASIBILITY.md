# CebianX 自动化测试可行性评估

> 版本: 1.3.1
> 评估日期: 2026-06-15
> 依据: FUNCTIONAL_TEST_CHECKLIST.md（共 135 个测试用例）

---

## 评估标准

| 等级 | 含义 | 说明 |
|------|------|------|
| **full** | 完全可自动化 | 纯 UI 交互、状态管理、DOM 检查、流程验证。可通过 Playwright + Mock 服务器 100% 自动化执行和断言。 |
| **partial** | 部分可自动化 | 流程（打开页面、点击按钮、发送消息）可以自动化，但**预期结果涉及 LLM 输出质量判断**或复杂视觉判断，需人工复核。Mock 服务器可固定返回内容，使流程跑通，但无法自动断言"要点清晰"、"分析正确"。 |
| **manual** | 需要人工 | 涉及真实第三方登录、人工确认、跨浏览器安装、存储配额满等难以在自动化框架中稳定复现的场景。 |

## 结论与建议

1. **优先实现 full 用例（92 个）**：这些用例完全依赖 UI 和状态，可通过 Playwright 自动化框架稳定运行，是回归测试的核心。
2. **partial 用例（31 个）作为辅助**：用 Mock LLM 固定返回预设内容，确保流程跑通； nightly/CI 中运行，输出结果供人工抽样复核。
3. **manual 用例（12 个）纳入发布前人工测试清单**：在版本发布前由 QA 手动执行，补充自动化覆盖盲区。
4. **断点续跑机制**：针对 full 和 partial 用例实现断点续跑，manual 用例跳过，避免重复运行。
